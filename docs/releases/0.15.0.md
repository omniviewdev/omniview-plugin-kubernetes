# Kubernetes 0.15.0

## Highlights

Find the columns you need without losing sight of your selection. Searchable column workspaces with a persistent **Selected** pane now cover Pods and 45 more Kubernetes object views, including the default custom-resource table.

- Search fields, labels and annotations by their full key.
- Select or clear matching results without changing unrelated columns.
- Keep required columns locked, preserve saved choices and restore defaults with Reset.

## Container logs

- Report readiness before the first log line, including silent follow streams.
- Complete finite empty streams normally and preserve output emitted before the host attaches.
- Unblock canceled sessions when output queues are full.
- Honor `SinceTime` by clearing Kubernetes' mutually exclusive `SinceSeconds` option.

These fixes use the compatible plugin SDK 0.14.5 and require the matching host log lifecycle fixes in Omniview 0.27.1 ([#187](https://github.com/omniviewdev/omniview-plugin-kubernetes/pull/187)).

## Compatibility and release ordering

**Requires Omniview IDE 0.27.1 or newer.** Upgrade the host before installing Kubernetes 0.15.0. The plugin builds against the published 0.27.0 runtime/Vite cohort; host/runtime 0.27.1 supplies the matching log lifecycle fixes. Marketplace publishing enforces host 0.27.1 as the minimum.

For maintainers: publish and make the Omniview 0.27.1 desktop and npm release available before publishing this plugin. Plugin builds continue using the already-published runtime/providers/Vite 0.27.0 packages; do not republish those versions. The Pod foundation and all 45 object-view changes are merged into main. Complete integration and release-packaging checks for this cohort before creating the Kubernetes 0.15.0 release tag.

The release workflow validates this versioned notes file alongside all four committed version fields. It transfers notes separately from plugin archives and uses this file as the GitHub release body, without appending duplicate generated notes.
