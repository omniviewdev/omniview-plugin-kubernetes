# Kubernetes 0.20.0

## Resource-table rendering

- Retain unchanged decoded row bodies, stable filter options, and data-only cells across sparse updates. Use shared immutable-row sorting so status-only updates do not re-sort unchanged names.
- Keep drawer/activity subscriptions outside the row tree. Resolve changing admitted-record data only for the open row menu; removed records still lose their actions. Share tooltip and row-action popup ownership.
- Preserve keyboard access to namespace copy and filtering. Enter and Space activate the native filter button; failed clipboard writes show retryable feedback.
- Keep a bounded 32-row overscan buffer on each side, up from 24. This reduces exposed viewport gaps at the cost of more mounted rows and metric target demand.

The combined host, shared UI, and plugin sprint measured a production React fixture with 5,000 Pods on an Apple M5 Max with Metal GPU rendering. Four serial trials per side used a 10-second warmup and 10-second capture. These results do not isolate this plugin's contribution.

| Recorded no-update scrolling cost | Before | After |
| --- | ---: | ---: |
| Frame gap, p95 | 35.15 ms | 25.95 ms |
| Frame gap, p99 | 48.75 ms | 34.50 ms |
| JavaScript during capture | 1,295 ms | 1,184 ms |
| Style calculation during capture | 1,466 ms | 980 ms |

All eight unthrottled no-update trials completed the 12,000-pixel path without measured DOM coverage holes. Isolated shared-component checks reduced sort comparisons over 50 status updates from 249,950 to 4,999 and mounted tooltip roots from 121 to 10.

Tradeoffs remain: first-row startup median increased from 3,118 ms to 3,181 ms, resting DOM elements from 4,855 to 4,990, and healthy metric target slots from 2,544 to 3,080. Target slots are not Kubernetes request counts. Live-update p95 frame gaps were 33.75 ms without CPU slowdown and 196.00 ms at 2× slowdown; no-update p95 at 2× slowdown was 115.70 ms. Remaining frame stalls are not solved. No smoothness guarantee, live-cluster IPC speedup, M1 certification, or native WKWebView certification is claimed. Larger retained windows, row batches, and other regressing experiments are not shipped.

## Metric availability and history

- Share one runtime table observation over mounted metric targets. Load only visible metric columns in a visible document; settled unavailable values stay static rather than restarting loading animations. Preserve genuine zero, bounded, and absolute samples.
- Bound native endpoint failures to a fixed cooldown: 30 seconds for authorization or missing endpoints, 5 seconds for other failures. Authorization remains selector-scoped; a missing LIST endpoint's 404 is shared across selectors so scrolling to new Pod names does not re-probe it. Retain at most 256 failures per source generation; cache hits do not extend expiry, and reconnect retires the lane. Cancellation and budget stops are not negatively cached.
- Narrow singleton PodMetrics scans with an exact Pod-name selector while preserving namespace batching for multiple targets, continuation predicates, identity checks, and scan budgets. In the recorded real 1,000-running-Pod comparison, scanned objects fell from 13,800 to 6,310 and response bytes from 4,694,594 to 2,161,316. Readiness was unstable; this was not 1,000 healthy Pods. Request count did not improve, and query latency and RSS increased. No CPU or server-internal complexity gain is claimed. [Native scan evidence](https://github.com/omniviewdev/omniview-plugin-kubernetes/pull/221).
- Declare pointwise range reuse only for unchanged built-in fixed-query Pod recipes and only when the executing provider also opts in. Preserve compatible displayed history during partial updates and source null gaps at the displayed step. Missing pairs in an incomplete frame remain pending, not proven absent. Native metrics-server remains current-only; no synthetic history or range-to-current equivalence is inferred.
- Report bounded native scan calls, pages, objects, response bytes, outcomes, and cancellations through existing diagnostics. Isolated scale labs retain explicit ownership and private kubeconfigs.
- Keep Secret drawer drafts separate from shared cached row bodies.

## Cluster explorer

- Fit flat Table mode beneath search and view controls with one bounded table scroller, compact edge gutters, and a reachable final row. Keep provider logos in the Provider column rather than repeating them in cluster identity cells.
- Align compact card typography, action sizing, status labels, and selected-label insets with shared tokens. Tooltips show only available provider, connection, region, account, and environment facts without duplicate names.
- Use provider labels and known-region flags, infer EKS accounts from validated cluster ARNs rather than authentication role ARNs, and paginate attribute submenus in groups of 20. Retain global density rather than a local table toggle.

## Compatibility and release ordering

Requires Omniview 0.35.0 or newer, runtime/Vite 0.35.0, Base UI 0.17.2, and Editors 6.2.4. Upgrade the desktop before installing the plugin. The backend retains plugin-sdk 0.18.0, Go 1.27, and the macOS 13 minimum.

Publish and verify the compatible desktop and npm packages before distributing Kubernetes 0.20.0; npm publication alone does not update an installed desktop. Marketplace minimum IDE version is 0.35.0. The release workflow validates all four committed version fields and these notes, builds five platform archives, and gates publication on the existing production-archive smoke workflow. Recorded sprint evidence does not replace those release checks.
