# Kubernetes 0.17.0

## Native resource metrics

- Adopt the finite resource metrics API for Pod and Node CPU and memory, with physical units, source timestamps, explicit result statuses, and bounded reads from metrics-server.
- Publish Kubernetes-owned metric definitions and Pod PromQL mappings for host-coordinated native and external metric queries.
- Show shared metric cells and panels with provider selection, chart controls, and current resource request/limit references. Native metrics-server samples remain current-only; they do not invent historical data.
- Retire legacy Pod-native CPU and memory requests in favor of the finite API. See [Kubernetes-owned metrics](../native-metrics.md) for migration details, provenance, bounds, and source requirements.
- Tighten collection correctness with deduplicated CPU/memory scrape series, exact response-byte limits, page-atomic target results, rejection of null quantities, and bounded partial coverage when admitted batches exceed 64 namespaces.

## Compatibility

Requires Omniview 0.31.0 or newer. This release uses plugin-sdk 0.16.0, base-ui 0.16.0, editors 6.2.1, and the runtime/Vite plugin 0.31.0 cohort. Publish the compatible desktop before this plugin.
