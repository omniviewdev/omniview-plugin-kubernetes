# Kubernetes 0.21.1

## Connection and source stability

- Retry transient discovery failures (closed or reset connections, timeouts, HTTP/2 connection loss, 429 and 5xx) during connection start instead of failing the start. Read aggregated discovery in two requests when the API server serves it, with the per-version path as fallback.
- Do not report an unreadable cluster identity as a changed one. A transient failure to read it now reports `UNAVAILABLE` and keeps the stored identity; a connection start whose identity stays unreadable after retries fails with `UNAVAILABLE` instead of starting without it.
- Reset a connection's sources only when the API server is unreachable: any HTTP response to the liveness probe counts as alive, three consecutive unanswered probes are required, and a failed probe is ignored while informers still receive events. The probe now resolves `host:port` server addresses.
- Report retryable API failures on source open as `UNAVAILABLE`, `TIMEOUT` or `CONNECTION_ERROR` instead of a terminal `PROVIDER_ERROR`.
- Classify transport and server failures (timeouts including the TLS handshake, refused or reset connections, DNS, early end of stream, certificate verification, 500/502) instead of reporting `INTERNAL`. Failed connection starts, resource operations and log streams log a closed error class, reason and the Go type of the cause, never the error text.
- A kubeconfig context with no user, or one naming a missing user, no longer crashes the plugin; it connects without client credentials.
- EKS: the published REST configuration now authenticates, so pod exec, attach, node shell and port forwarding work with `aws eks get-token` and `aws-iam-authenticator` users.
- Workload port forwards survive reconnects: each tunnel has its own readiness signal, a fault in tunnel code ends that session instead of the plugin process, and the reconnect budget resets after a tunnel has been healthy for 30 seconds.

## API server load and resource use

- Enumerate and label queries size each native List to the room left in the page instead of requesting one object per List. A 1,000-object collection at page size 16 takes about 65 requests instead of about 1,000.
- Share one request rate limiter (50 QPS, burst 100) across the clients of a connection bundle; previously each client had its own. Finite requests have a 60 second ceiling; watches, logs and exec are exempt.
- Remember an absent metrics API per connection with backoff (30 seconds doubling to 10 minutes) instead of probing every namespace on every query, and log it once instead of on every scan. A scan that reaches its deadline returns the namespaces that finished. Namespace lists run four at a time and identical concurrent lists are shared.
- Helm: enumerate releases with one list per page and decode only the latest revision of each release. Cache parsed repository indexes within a 32 MiB budget, enforce the index size limit at refresh, and remove downloaded chart archives after use.
- Close idle API connections when a connection is retired.
- Identify plugin traffic with an `omniview-kubernetes/<version>` user agent.

## Diagnostics

- Informer, source, catalog, schema and action log lines that were previously discarded now reach the plugin log.
- When plugin profiling is enabled, block and mutex profiles are populated and CPU profiles carry bounded `phase` and `connection` labels. `docs/profiling.md` describes the procedure.

## Compatibility

Requires Omniview 0.36.0 or newer. Uses plugin SDK 0.20.0; dependencies are unchanged from 0.21.0.

A metrics API installed while a Pod table is open can take up to 10 minutes to be noticed; reconnecting the cluster clears the remembered absence. The EKS change is covered by tests against a local API server and has not been exercised against a live EKS cluster.
