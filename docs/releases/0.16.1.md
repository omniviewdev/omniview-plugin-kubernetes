# Kubernetes 0.16.1

## Production notification compatibility

- Rebuild the plugin from current source using the supported runtime `useNotifications` API, preserving the activity and cluster explorer changes from 0.16.0.
- Reject emitted production runtime setters that import retired `useSnackbar` before packaging. The affected older bundle assigned the missing export to minified `zs` at `entry2.js:332:197118`, crashing the cluster list before connection requests.
- Keep runtime-owned connection lifecycle notifications separate from plugin-owned warnings, clipboard failures, and folder updates.

The release guard and regression coverage are in [PR #209](https://github.com/omniviewdev/omniview-plugin-kubernetes/pull/209). Eight guard regressions passed before shipping. A managed development desktop exercised the cluster list and folder creation/deletion; this is not a packaged-desktop smoke test. The guard inspects emitted imports, not every possible host API interaction.

## Compatibility

Requires Omniview 0.30.0 or newer and retains the matching runtime/Vite 0.30.0 dependency cohort. Omniview 0.30.1 additionally isolates plugin child-route render failures so navigation can recover. Publish the compatible desktop before this plugin. The marketplace minimum remains 0.30.0, the actual API compatibility baseline.
